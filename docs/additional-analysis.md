# 論点型追加分析とPDF CMap


## 追加分析の論点化とCMap同梱（2026-10-06 / v100）

追加分析v3は固定の「解釈・短期・中期・長期」から、通常2〜4件の重要な論点へ変更する。根拠が不足する場合は1件または0件を許し、形式を埋めるための「判断不能」は要求しない。各論点は結論・根拠・条件付きの読み・限界・次の確認点を持つ。

- Backgroundは元PDFとの再照合後、確定事実に加え、点検済みの会社説明・観測指標を追加分析へ渡す。未点検/却下された説明は根拠へ昇格させない。期間形、対象、範囲、会計基準、限定条件、分割調整・分母・日付役割を保持する
- 表示する根拠本文・数量・ページはコードが構成する。モデルは根拠IDを選び、結論と読みは推論として表示する。ID照合、数値リテラル拒否、単純な重複/完全一致の拒否は意味・有用性の完全な検証ではない。因果、継続性、将来予測の正しさを保証しない
- 同条件の差額、累計実績対通期予想の残額・進捗、営業CF＋投資CFを正確な十進数で計算する。主体/範囲/基準/期間/単位/条件が不一致または曖昧な組は省略し、EPS・率・範囲値・上限/下限等を加算可能な点の金額として扱わない。利益の負数・ゼロ分母から通常の進捗率を作らない。残額は会社の残り期間予想ではない
- 根拠ページは論点ごとに重複を除き、詳細IDは展開式にする。説明/指標の不足と、入力があるのに論点を生成できなかった場合を区別する。入力件数・未整理原文・未確認事実・使用量/終了理由を残す。1要求・60秒・最大8,192出力token、暗黙の再試行なし
- 保存したv3は入力識別子と表示根拠を再照合する。全体指紋v100と `analysisCacheV3:` により旧抽出/旧時間軸形式を再利用しない。同じ結果を閉じて開き直す場合も、古い応答や保存読込で新しい分析を上書きしない
- インストール済みPDF.jsと同版のpacked CMap全体とそのLICENSEを `dist/cmaps/` へbuild/watch時に出力する。Offscreenは拡張内部URLと `cMapPacked: true` を指定する。CDN、追加ホスト権限、CSP緩和、CMapのweb-accessible公開は使わない

CMapの通常テストは実パッケージを読む `buildStart` の出力・バイト一致・監視対象・再実行時の再出力を直接確認し、Vitest内ではViteを起動しない。実ビルドへの接続は通常の `npm run build` 後に `check-cmap-artifacts.mjs` で確認する（展開済みZIPやwatch出力も引数で指定可能）。既存releaseのビルド直後にも同じ検査を実行し、プラグイン接続漏れをZIP作成前に止める。タイムアウトの一律延長や二重ビルドはしない。

今回の追加証明は部品の計算/参照/保存契約、代表的なBackground入力受渡し、実Reactの競合・閉じる/再表示、CMap資産の同梱、固定応答による指定実PDFの経路に分担する。同じ資料を全経路の語彙網羅へ複製しない。実モデル品質と実Chrome確認の境界は評価ガイドを参照する。

## 生成契約と追加分析専用診断（2026-10-09 / v119）

ファーストブラザーズの指定PDF `140120261008547944.pdf` で報告された「追加分析の形式・根拠参照が不正です（事実19・説明9・指標15・計算12、出力1215token）」は、生成後の形式・根拠参照境界の失敗だった。利用者から提供された診断には要約の三段階だけがあり、失敗した追加分析の生応答は含まれていなかった。個別の失敗項目は特定できておらず、再現用の合成応答を当時の失敗応答として扱わない。

- `ANALYSIS_LIMITS` からプロンプト・応答JSON Schema・ローカル検査を揃える。論点は最大4件、根拠は論点ごとに1〜6件、見出し80文字・各本文350文字。文字数はJSON Schemaと同じUnicodeコードポイントで数える。空白だけ、プレースホルダー、数値生成、重複、単なる完全一致の言い換えは引き続きローカルで拒否する。
- モデルへ渡す根拠は `evidence[].id` の単一の引用名前空間と `allowedEvidenceIds` に限定する。原文セル・段落等の `sourceIds` は生成用投影から外すが、内部の検証済み入力・表示根拠・保存再照合には残す。原文IDを黙って書き換えたり、不明なIDを推測で対応付けたりしない。
- 既知のモデル能力がある場合だけ `json_schema` を送る。他のプロバイダーは従来のJSON modeまたはJSON指示に従い、必ず同じローカル検証を通す。非対応エラーを課金付きの暗黙の再要求で補わない。
- 失敗は安定した `code` とJSON `path` で区別する。形式、文字数、欠損・重複・不明参照、JSON不正、上限打切り、中断などを同じ曖昧なメッセージへまとめない。コード・位置は境界を示すだけで、モデルがそう出力した理由や推論の正しさを保証しない。
- 追加分析の各実行に独立したrun IDを付け、元の要約result ID、入力hash、引用可能IDと制約、生応答、使用量・終了理由、失敗位置を専用の容量制限付き診断へ保持する。要約診断を置き換えない。切詰めは診断に明示し、保存失敗は表示結果を止めず警告する。生成前の未受信 `null` と受信した空文字を区別する。診断の保存待ち時間をモデルの60秒生成期限へ混ぜない。
- 表示中の成功結果の診断と、直近に開始した試行の診断は別々の参照・ボタンにする。初回の失敗後も再読込から失敗診断を開ける。遅い旧応答で直近の試行を置き換えず、別の要約結果・入力には混ぜない。保存上限による消失は明示し、全保存が失敗した診断を再読込後に復元できるとは扱わない。
- 同じ段落の別の説明が採用されていても、未確認・不採用の項目を分析の入力範囲から消さない。入力・表示・保存再照合へ、件数・原文ページ・制約を非引用のcoverageとして渡す。却下された文章を根拠へ昇格させず、資料に一時要因や時期の説明が存在しないと断定しない。今後の説明生成には、条件・否定・因果の範囲を保った独立した論点と、数量の原文所有者の明示を求める。

固定検査の責務は、部品の文字数/参照の正負境界、生成形式と診断observer、Backgroundの実行別保持、保存上限・失敗、Reactの再試行・閉じる/再表示・診断コピーに分ける。指定PDFの既存三応答を再生する検査は、要約の原文照合と追加分析入力の保持を証明する。元の失敗した追加分析応答や、新しいプロンプトでの実モデル品質を再現したとは扱わない。実モデル評価・公開はこのローカル修正には含まない。

## 推論と検証境界の分離（2026-10-09 / v120・追加分析v4）

v119の実応答で、`第2四半期`・`第3四半期`・`第4四半期`の数字が本文の数値禁止に触れ、全体が失敗した。同じ期間を漢数字に変えるだけで通ることも確認した。期間ごとの例外や表記変換を足すのではなく、次の責務へ分け直す。

- **原文対応のある根拠・機械計算**は従来どおりコードが構成する。生成文章の金額・率・計算式から根拠を追加・書き換えない。引用IDは対応だけを検査し、推論の正しさを証明した扱いにしない。
- **生成文章**は数字・期間を含めて原文のまま保持する。論点名・結論・読み・限界・次の確認のすべてが未検証のAI推論であると画面で明示する。量的な予測も、根拠欄の照合済み数値とは別の主張である。
- **論点ごとの形・参照の不備**はその論点を隔離し、元の位置と理由を表示する。他の論点は保持する。隔離した本文や不正IDを正常な根拠に結びつけて表示しない。軽微な追加キー・任意の限界/確認欄の欠落・重複IDは警告し、安全な表示投影だけを作る。本文の意味を書き換えず、重複IDを一つにまとめたことも明示する。
- **長さや反復**は品質上の注意とする。推奨は4論点・見出し80文字・本文350文字・根拠6件。別の実行安全上限は16論点・各本文4,096文字・根拠32件・応答256KiB・構造深さ32・10,000ノード。個別本文/参照上限は論点を隔離し、全体容量/構造上限や読めないJSON・未対応の形式は全体を停止する。保存封筒には原候補と派生表示の重複分があるため、1MiB・40,000ノードを使う。
- **出力打切り**でも完全なJSONと表示可能な内容がある場合は、未完の可能性を全体の注意として表示する。不完全JSONから文章を補完・推測しない。終了理由・原応答は診断に保持し、自動再要求は増やさない。
- **保存**は追加分析v4/`analysisCacheV4:`と全体指紋v120に分離する。原候補から論点・注意・隔離を再計算し、保存した派生表示、入力hash、コード構成の根拠、coverageと一致するものだけを戻す。整合性検査であり、生成文章の意味や保存データの暗号学的な真正性の証明ではない。旧v3を新しい推論表示へ黙って移行しない。
- **診断**の封筒v1は旧記録を読めるまま、契約version=4と`partialSuccess`を追加し、個別の注意/隔離理由と実行安全上限も診断コピーへ残す。表示できる論点がない全隔離と、モデルが明示的に空配列を返した場合を注意情報で区別する。コピーは「要約」「表示中の追加分析」「直近の追加分析」を明示し、保存済み表示と後続の失敗を混同しない。

### 意味上の限界

同じ実応答には、入力に固定資産売却益1,174,729千円と経常利益進捗79.0%があるのに、その金額・進捗が未確認という文章もあった。生成指示では入力全体を確認し、既知の金額と不明な寄与内訳・今後の予定を区別することを明記した。しかし一般的な矛盾・因果・「記載がない」という主張を決定論的に検証したとは扱わない。今回の表示変更はこの文章を黙って修正しないし、根拠IDが正しいだけで正しい説明として認証しない。追加の有料モデル点検や再試行は導入しない。

### 検証の担当と公開範囲

部品は表記を問わない本文保持、正常/不正/正常の論点分離、構造予算、原候補からの保存再照合を担当する。Background/診断は部分結果・原応答・最新試行と既存表示の分離を担当する。React結合は部分表示、閉じる/再表示、再読込、コピーする診断の同一性、追加APIなしの復元を担当する。HTMLは本文・警告・根拠・リンクのエスケープを検査する。
