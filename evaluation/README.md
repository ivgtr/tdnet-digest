# 評価ガイド

`evaluation/` には、文書分類の回帰テスト用データ、公開 TDnet PDF の参照情報、実 PDF を使うローカル評価スクリプトを置いています。

## データと評価範囲

| ファイル                             | 内容                                                          |
| ------------------------------------ | ------------------------------------------------------------- |
| `fixtures/classification-cases.json` | 合成タイトル36件の期待分類と、一部の決算コンテキスト          |
| `fixtures/real-pdf-cases.json`       | 公開 PDF 18件の公式 URL、期待分類、抽出確認語                 |
| `scripts/check-real-pdfs.mjs`        | ローカル PDF のページ抽出、空ページ、確認語のチェック         |
| `scripts/run-real-llm.ts`            | 指定した1件を2パスで要約し、JSON 検証結果と出力をローカル保存 |
| `fixtures/fact-summary-cases.json`   | 決算・業績修正・提携の事実要約に必要な値と物理ページ          |
| `scripts/run-fact-summary.ts`        | 現行の1回構造化要約と原文照合を実PDFで評価                    |

通常の `npm test` はタイトル分類や原文照合などの回帰テストです。投資判断の有用性は測りません。従来の実 PDF スクリプトは空ページと指定語の有無を確認します。事実要約の3件については、主要数値・単位・期間・物理ページの期待値を別のfixtureに記録しています。

## 実 PDF の確認

`fixtures/real-pdf-cases.json` は31日で公開終了するTDnet閲覧URLではなく、JPX・名証の過去開示PDFを参照します。初回は `--fetch` を付けると、欠けている公開PDFだけを順に取得して検証します。PDF 自体と抽出テキストは Git 管理しません。

```bash
npm run test:real-pdf -- --fetch
```

成功時は `evaluation/fixtures/real-pdfs/text/` にページ境界付きテキストが生成されます。PDF が欠けている場合は結果表に `missing` と表示され、コマンドは失敗します。

## LLM によるローカル評価

LLM API を呼び出すため、利用するサービスの料金が発生します。`.env.example` を `.env` にコピーし、プロバイダー、モデル、API キー、対象ケース ID、PDF ディレクトリを設定します。

```bash
cp .env.example .env
npm run test:real-llm
```

対象は1回につき1件です。`TDNET_DIGEST_API_KEY` の代わりに、選択したプロバイダーに対応する `OPENAI_API_KEY`、`ANTHROPIC_API_KEY`、`OPENROUTER_API_KEY`、`GOOGLE_API_KEY` も使用できます。実行結果は Git 管理外の `evaluation/results/local/` に保存されます。API キー、非公開資料、個人情報をコミットしないでください。

結果を比較する際は、同じ抽出テキスト、モデル、設定を使い、数値・単位・比較期間・根拠ページを原文と照合してください。PDF にない市場コンセンサスや現在株価を正解として補わないでください。

## 現行の事実要約を3件で評価

`fixtures/fact-summary-cases.json` の3件のPDFを記載URLから取得し、`evaluation/fixtures/real-pdfs/<ID>.pdf` に保存します。`.env` に `TDNET_DIGEST_PROVIDER`、`TDNET_DIGEST_MODEL`、`TDNET_DIGEST_API_KEY` を設定して実行します。

現行の評価設定例はOpenRouterの `deepseek/deepseek-v4.1-flash` です。ローカルの `.env` が旧モデルを指している場合は、モデル名を更新してから実行してください。

```bash
npm run test:fact-summary
```

1件だけ実行する場合は `npm run test:fact-summary -- earnings-20260813` のようにIDを渡します。ページ抽出は拡張と同じ行の組立処理を使い、構造化結果を原文と照合します。必須の数値・単位・対象期間・物理ページが一致しない場合は失敗します。結果はGit管理外の `evaluation/results/local/` に保存します。`run-real-llm.ts` は旧2パスの比較用です。

## 位置情報を使う表照合の回帰評価

`src/lib/fixtures/pdf-layout-corpus.json` は公開PDFの指定ページから取得したPDF.js文字アイテム（文字、transform、幅、高さ）です。通常の `npm test` で本番と同じ `extractPageLayout` を通し、セル参照と期待値を検証します。PDF本体・API応答・秘密値は含みません。

| PDF ID             | 会社・確認対象                                                 | 取得元・物理ページ                                                |
| ------------------ | -------------------------------------------------------------- | ----------------------------------------------------------------- |
| 140120260929541758 | フィードフォースグループ：EBITDA列、実績・通期予想・配当11項目 | https://www.release.tdnet.info/inbs/140120260929541758.pdf / 1・2 |
| 140120260709590576 | クリエイト・レストランツHD：IFRSの四半期利益と親会社帰属利益   | `fixtures/real-pdf-cases.json` / 1                                |
| 140120260708589925 | ギークリー：通期実績                                           | 同上 / 1                                                          |
| 140120260714592721 | CaSy：中間期、赤字・欠損増減率                                 | 同上 / 1                                                          |
| 140120260714593367 | 明光ネットワークジャパン：配当決定額と直近予想、円銭           | 同上 / 1                                                          |

実PDFを `evaluation/fixtures/real-pdfs/<ID>.pdf` に置いた状態で、次のコマンドが保存した位置情報との一致・抽出時間・文字数・通信サイズを確認します。環境ファイルとAPIは使用しません。

```bash
node --import tsx evaluation/scripts/check-layout.ts
```

今回の6ページでは本文8,184文字に対しLLM入力46,070文字。Offscreenから渡すページデータは合計145,741 bytes。抽出は初回PDF.js初期化込み約0.95秒、後続PDFは約43～89msでした（分析指紋v22の実装で、この環境での1回の測定）。LLMトークン数・料金・API時間はこの測定に含みません。

`fact-summary-release.test.ts` は検証済み事実を要約HTMLと採点まで渡す結合テストも含みます。API応答は固定データであり、実モデルの抽出精度は別途 `test:fact-summary` で評価します。同スクリプトも本番と同じ位置情報付き抽出を使用します。

`numeric-evidence.test.ts` と `score-extraction.test.ts` では、数量が1つだけの表（値と一体の単位、列単位、共通単位）、要約と採点での根拠共有、第2・第3四半期の累計見出し参照を合成座標データで確認します。修正前には単一数量表と空引用の累計表が失敗することを再現しました。期間・単位の別列参照、単独期間との混同、累計見出しの参照欠落は引き続き拒否します。

本文中の助詞・句読点と、店舗・人・件などの非財務単位も修正前の失敗を再現しています。複合助詞「については」「として」などは語単位で照合し、6文字の上限と否定・概数表現の拒否も確認します。本文は別指標・別数値・別の文を跨がないこと、要約の対象行の実績／予想区分を維持することを確認します。数量解析は `quantity.test.ts` で円銭・負数・割合・非財務単位を確認し、複数の数量や不明値は拒否します。PDF抽出では数値と後続語を別IDで保持し、「合計」などの項目名を失わないことを確認します。隣接単位は別IDの位置と文字列から照合し、店舗・人・件のPDF抽出から要約・採点までの経路と、不正な位置の拒否を確認します。数字で始まる指標見出しを数値行と誤認することも防ぐ回帰テストを追加しています。

Chromiumにビルド済み拡張を読み込む一時的なPlaywrightスクリプトでも確認しました。対象PDFは実ファイルの全11ページをOffscreenで抽出し、TDnet一覧とAPI応答だけを固定しました。11項目の要約、ヘッダー「AI要約」、要約下部のスコア表示、採点API失敗後の再試行、非表示・再表示によるキャッシュ復元を確認しています。API呼び出しは固定応答への4回（要約、失敗した採点入力、再試行した採点入力、採点）で、再表示時には増えません。実サイトのCSS・一覧構造全体や、実LLMの抽出成功を保証する確認ではありません。
