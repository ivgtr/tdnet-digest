# Phase 5: 構造化出力の検証と修復

## 実施内容

- LLMプロバイダーのJSON出力能力を分離し、OpenAIではJSON objectモードを利用
- パス1応答に対し、JSON解析、文書別必須フィールド、投資判断の方向性、配列上限、根拠ページ範囲を実行時検証
- 検証失敗時は、元PDFを再送せず、壊れた応答・検証エラー・出力形式だけで1回修復
- 修復後も不正な場合は、生のJSONを表示せず1パス要約へ安全にフォールバック
- Anthropic、Google、OpenRouter、カスタムAPIは能力を過大評価せず、プロンプト制約と実行時検証を使用

## 自動検証

- 全95テストが成功
- JSONコードブロック除去、必須フィールド欠落、不正enum、件数超過、PDF範囲外ページ、修復指示、OpenAIリクエスト形式をテスト
- TypeScript型検査、ESLint、プロダクションビルドが成功

## 評価上の制約

実APIで各モデルのJSON遵守率と修復成功率は未測定です。プロバイダーやモデルごとに対応状況が変わり得るため、未知の互換APIにはJSONモードを自動適用していません。
