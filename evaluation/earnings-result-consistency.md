# 決算要約の結果整合性と操作ストーリー

基準は main `5cd5e6e` / v0.7.9。分析指紋を v108 に更新し、旧抽出・旧表示の成功キャッシュを新しい結果として使わない。実行履歴の保持は要約キャッシュとは独立する。

## 不具合と修正の境界

- 別の閉セルの金額と増減率が近いと、横方向の数量組立が結合していた。`3,963,389` + `16.6` は数値として消え、`100` + `20` は誤った `10020` になり得た。原文字→span、円銭の再結合、span→quantity、段落の横連結/折返し、表示用数量、保存原文の再検証で同じ物理セル所有を使う。最小の一意な閉セルだけを証拠とし、別セル・曖昧な所属を結合しない。距離閾値は縮めず、同セルの符号・小数・桁区切り・範囲を保持する。
- 冒頭は当期より `key` を優先していた。原文表紙と連続する明示フィールドの対象期・主体・連結/個別・会計基準を使い、当期の主要実績を固定順で選ぶ。前年・予想・率・EPS・別主体/範囲を欠損の代用にしない。不明なら推測せず明示し、確認済み本文は残す。標準決算の表は対象期・実績/予想別に分ける。
- 26頁を通した確認で、2頁の個別業績表の「経常利益」が連結IFRSの必須項目に混ざる不足も見つかった。必須指標の宣言元にも報告対象の主体/範囲/基準を適用する。明示的な別属性だけを除き、属性未解決を理由に義務を消さない。「税引前利益」を「経常利益」に改名しない。
- 診断は全体の最新1実行から、実行ID別の保持へ変更。保存結果にも実行IDを残し、JSON取得でPDF URL・結果ID・実行IDを照合する。別の実行の診断を借りない。保存読込/コピーを理由にAPIを再実行しない。

## 診断の保持契約

- `summaryDiagnosticsV1` は Background の直列queueで1キーを原子的に更新する。
- 最大12実行、ストアJSONのUTF-8最大2 MiB、1実行最大192 KiB。長い生応答等を省略した記録は `compaction` に元サイズと理由を残す。識別子・ハッシュ・成否は切り詰めない。
- 追加するrunを保持し、古い完了runを先に除く。すべて進行中でも上限は維持する。診断の削除で要約本文のcacheは消さない。
- 旧最新診断は厳密一致するときだけ利用する。新規保存時には同じ上限で移行し、新storeの保存後に旧キーを削除する。整理失敗は成功本文/保存済み診断を残して警告する。
- APIキー、認証ヘッダー、設定一式、APIエンドポイントは診断オブジェクトへコピーしない。許可した診断フィールドだけを投影する。
- Optionsの既存cache削除は要約/採点/追加分析が対象。診断はこの有限保持で独立して整理される。診断管理UIや無制限の履歴は追加しない。

## 罫線セルの属性欄と欠損境界（再レビュー）

再レビューのP1を、罫線付きの原文字入力から再現した。`会計基準 │ 日本基準`や`範囲 │ 連結`の区切りが値へ混入し、会社名にも混ざる。会社名と属性が同じ行にある場合は管理情報として行全体を除外していた。

- 会社名・範囲・会計基準・株式種類を読む共通のメタデータ投影を追加。同じ行の明示ラベルと値だけを対応させる。別ラベル、空欄、改行の先から値を借りず、元の引用や数値検証用テキストを連結しない。
- 罫線の所属が一意で、左右の辺と上下範囲が一致する隣接セルだけを単一の`│`で示す。空セルを飛ばす場合、片側が所属不明、所属が重複する場合は`││`で未証明の境界を保つ。どちらも数値の結合を止める。空の「当社」列を越えて「参考会社」の名前を借りる反例も拒否する。
- 構造セルを分割して得た裸の語句を属性欄へ昇格させない。実PDF再生で見つけた、配当表の列見出し`(連結)`が配当の範囲になる誤りを修正。改行後に同じ見出しだけが残る場合も拒否する。後続の明示欄は独立に読み、重複した異なる基準は曖昧として残す。
- 混在する会社欄を原文一覧へ残す。取得対象株式の種類も同じ欄の読み方に揃える。配当支払開始予定日は隣接セルの明示日付を原文のまま表示し、Unicodeの横方向空白は受け入れるが、空欄・改行・未証明境界は補完しない。
- 語彙・空欄・別欄・折返しの負例は部品テスト、実罫線の分離/混在/折返しは原文字→文脈→候補→冒頭→保存再検証で担当する。空の当社列・所属不明・重複所属も実座標の負例とし、既存の金額・率・符号・桁・単位のセル境界テストは維持する。この対応時点では1,345テストと全26頁の固定再生を確認した。実API・実ブラウザーの検証範囲は拡張していない。

## 区切り・必須枠・数量損失・予想対象の追加監査

次の4指摘もすべて再現して修正した。共通する不足は、同じ意味を持つ入力表記や表示状態の片側だけを検査していたことと、結果が空でも通る検査だった。

- `|`・`｜`・`│`を同じ規則で扱う。どの区切りでも、表の裸の列見出しや折返し語句を会社・範囲・会計基準へ昇格させない。区切りのない単独宣言と、明示ラベル付きのセルは保持する。
- 再生fixtureの必須枠を、原資料に対応する固定13件（当期4・前年4・通期予想4・配当1）の完全一致で検査する。生成前は全枠の根拠ID、生成後は全枠の充足を確認し、空配列・当期枠の全欠落・1枠欠落・重複・根拠なし・未充足の負例を置く。23件の確定事実も実際の件数を確認し、報告値を期待配列の長さだけから作らない。
- 重複セルで所属不明の数値が、隣の一意なセルにある独立した数量まで消費しないようにする。前後両順序と、同一セル内で小数・桁区切り・範囲の途中から分割された入力も確認。真の未完断片、壊れた同一セル数量、所属不明同士を短い正常値へ読み替えない。
- 決算短信の修正後予想は、必須判定と同じ原文の予想宣言へ照合してから冒頭に載せる。主体・連結範囲・会計基準・予想期・累計/単独を照合し、未宣言・属性不明・競合時は生き残った数値から対象を作らない。別の報告単位の確定事実は本文に残す。当期の期と予想期は独立して扱い、当期表題の曖昧さが明示された予想宣言の解釈を壊さない。
- 保存データだけの検査は従来の整合性検査として維持し、PDF付きの再検証では対象外の修正後予想を冒頭へ追加した保存値を拒否する。通常の生成→表示→JSON復元→HTMLに加え、順序反転・正しい予想値の除去・別年度/四半期・別会社/範囲/基準・曖昧な宣言を確認する。
- 最終版の1,373テスト、type-check・lint・build、全26頁の固定再生が成功。独立固定23数量と必須13枠、候補修復なし、保存再検証を確認した。実API・実ブラウザーの検証範囲は拡張していない。
